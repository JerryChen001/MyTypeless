# 2026-10-15 会议：自动区分说话人加强、随时改名、结束时可只保存记录（D-018、D-019）

## 背景

用户反馈：① 按声纹区分人太难用，希望检测到不同声纹就自动区分，之后随时改名；② 会议结束时可以选择不生成摘要、只保存会议内容。用户确认改名时默认记住声音（可取消）。查看本机数据库（只看结构统计）：尚无会议记录，声纹模型已下载——判断痛点在于流程（命名 + 勾选）与区分可靠性。

## 真人录音评估

此前只用系统朗读声音测过。改用 sherpa-onnx 公开的真人 4 人中文录音（`0-four-speakers-zh.wav`，57 秒），以 sherpa-onnx 官方完整流程（pyannote 分段 + CAM++ + 聚类，指定 4 人）为参考：说话人序列 0,1,1,2,0,3,3,3,2,0。

| 版本 | 结果 |
| --- | --- |
| 原实现（停顿切句 + 整句声纹） | 13.8～17.0 秒整句漏掉（没转写）；48 秒的一句被“零散说话人吸收”错并 |
| 修 VAD 底噪 + 吸收门槛提到 0.5 | 不再漏句；但 0～10.8 秒、11.3～17.1 秒各把两人并成一句（不停顿接话），两人声纹混在一起 |
| + 每句用分段模型找句内换人（无参考录音） | 离线评估正确；经应用真实采集管线时句子边界略有不同，短片段里分段模型分不清人，仍有两处错 |
| + 带前 8 秒参考录音、同一人相邻段合回 | 应用内（假麦克风播放该录音）12 段全部归对，与参考一致；切点比真实换人晚约 0.5 秒，丢了 3 个字 |

- 根因一（VAD）：底噪估计让所有非语音帧参与平均，说话中较轻的部分把底噪一路抬高（阈值涨到约 1200），下一句正常音量（中位数 1145）被当成静音。改为贴着最安静的帧更新。此修改同时作用于听写的实时转写（D-013），自动测试全部通过。
- 根因二（接话）：真人对话常常不停顿就接话（实测间隔 0.12～0.15 秒），只按 0.6 秒停顿切句必然把两人并成一句。
- 参考录音长度：8 / 10 / 15 秒结果相同（15 秒切点更准约 0.3 秒），8 秒处理 57 秒录音约 2.7 秒 CPU（单线程），选 8 秒。
- 分段模型用量化版（1.5MB，与未量化版结果一致）；句内聚类阈值 0.4～0.7 结果相同，保留 0.7。

## 改动

- `mt-diarize` 新增 `turns` 命令（sherpa-onnx 离线说话人区分，只用来找换人位置）与 `--segmentation` 参数；声纹模型改为两个文件（CAM++ 28MB + 分段 1.5MB），已下载 CAM++ 的用户开会或在设置里补下 1.5MB。
- 会议每句：带前 8 秒参考录音找换人 → `splitByTurns` 切开（短于 1 秒的碎片并入前段，切出的段不短于 1 秒）→ 各段算声纹 → `mergeAdjacentParts` 同一人相邻段合回 → 逐段识别、归类、落库。
- 界面：会议详情顶部新增说话人栏（自动出现的每个人一枚标签，显示句数）；点标签或发言前的名字弹出改名小窗（「记住这个声音」默认勾选、回车确定，下方可合并到其他人）；结束会议、继续整理时选择「生成纪要 / 只保存记录」；浮动条的结束按钮弹系统对话框三选一；托盘提供两种结束方式。

## 验证

- `npm run typecheck`、`npm run test`（57 项）、`npm run build`、`npm run docs:check` 通过。
- 打包版隔离实例：模拟用户状态（只有 CAM++）→ 设置里补下分段模型 → 播放真人录音开会，12 段全部归对；点名字改名为「主持人」后标签与转写同步、声纹默认保存；结束时选「只保存记录」：状态已完成、无纪要、纪要页提示可生成、临时录音已删除。
- 未验证：浮动条结束按钮的系统对话框（自动化无法点击）；用户真实会议环境（单台电脑麦克风、远场、多人同时说话）。

## 追加：同一个声源分不出不同的人

用户反馈：“同一个声源无法区分出不同的声纹”。其测试会议已删除，无法查看数据；判断为多人声音经同一出口（电脑外放、一台麦克风、同一房间）进入，共同的声道成分让所有人的声纹变像。

- 复现：真人 4 人录音模拟外放（350Hz～5kHz 带通、1.2kHz 共振、房间回声、压缩、粉噪）。原实现与“归一化中心”比较时，不同的人升到 0.49～0.53（门槛 0.5）被并成一个；且第二个人一句话低于 VAD 固定下限 450 被当成静音。
- 尝试“减去本场平均声纹”（抵消共同声道）：外放下不同人降到 0.13 以下，但全场一个人时只剩噪声、把一个人拆成几个（真人单人 3 段 → 2 人，肯尼迪演讲 4 段 → 3 人），弃用。
- 关键发现：两两原始相似度本来就分得开（同一人最低 0.60～0.66、不同人最高 0.44～0.53），问题出在与**归一化中心**比较——多段平均后共同成分被放大。改为**平均链接**（与某人每段的平均相似度 = 归一化向量 · 未归一化平均向量），门槛 0.5～0.6 在 5 组数据（真人原声、模拟外放、合成单人、两组真人单人）上全部正确，取 0.55。
- 实现：在线归类、整体归类（最近邻链平均链接层次聚类，O(n²)，带锁定/命名约束、参会人数）、句内同一人合回、声纹认人与保存（存未归一化平均向量）全部改用平均相似度；会议中每 20 秒（有新段时）整体重新归类并重建在线归类器；结束时「说话人 N」按出场顺序重新编号。VAD 下限 450 → 250（20 秒纯粉噪不误判）。
- 回归数据：`test/fixtures/speakers.json`（5 组真实录音声纹，保留 4 位小数），在线与整体归类都要全对。
- 应用内验证：模拟外放录音经真实采集管线，第 25 秒时已出现的人全部分对，结束后 4 人 11 段全对；上一场用原声命名并记住的「主持人」经外放仍被自动认出。
- 附带修复：应用被强制退出时 `mt-whisper` 不随之退出（发现两个测试实例的残留引擎各占约 770MB）——启动时清理父进程为 launchd 的残留引擎，已验证。

## 追加：真实二人会议仍未区分——路径空格导致声纹全部失败

- 用户真实开了二人会议（7 分 44 秒、65 句）：结构统计显示 63 句说话人为空（未区分），2 句为用户手动指定——声纹计算根本没有成功过。
- 根因：`mt-diarize` 按空格解析 `embed <文件> <起> <数>`，真实临时录音路径 `~/Library/Application Support/...` 含空格被截断，每条命令都返回 `bad command`；结束时补算同样失败，录音整理完即删除，这场会议无法补救。此前所有隔离实例测试的数据目录（`/tmp/mt-smoke/...`）不含空格，问题未暴露。
- 修复：命令改为 `embed|turns <起始样本> <样本数> <文件>`，路径取到行尾；声纹计算一次都没成功且连续失败 3 次时浮动条提示“说话人区分暂时不可用”，错误原因写入日志。规则写入 AGENTS：隔离测试的 `--user-data-dir` 必须带空格。
- 验证：已安装版本的 `mt-diarize` 用带空格路径复现 `bad command`；新版本带空格路径 `embed`/`turns` 正常、错误路径返回 `open failed`；打包版以 `/tmp/mt smoke/ud6` 为数据目录播放真人 4 人录音开会，10 段全部归对。

## 追加：真实二人会议被拆成 16 人（D-020）

- 结构统计：174 秒、41 句，分出 16 个说话人（最大一组 17 句，多数 1～2 句）；句长以 1～2 秒为主（19 句）。用各说话人保存的平均向量算组间平均相似度：同一人被拆开的组之间 0.47～0.55，刚好低于 0.55。
- 评估数据：sherpa-onnx 说话人识别测试集 sr-data（Apache-2.0，5 位真人）切成 1～2.5 秒短句（原声与模拟外放），统计：同一人两句 5% 分位 0.07～0.18、中位 0.55～0.60；不同人中位 0.05～0.22、95% 分位 0.31～0.43——固定门槛必然两头为难。组合出单人/两人/三人对话共 47 个场景（中文；含英文录音的说话人跨语言、跨场合，内部只有 0.31～0.37，不代表会议）。
- 方案比较（人数判对）：固定 0.55 为 12/47；降低门槛 0.30～0.45 为 7～17/49；谱聚类（特征值间隙）不优；平均链接 0.4 + 零星小组（< max(5 秒, 5%)）并入最像的主要说话人为 37/47（原声 24/24 全对，外放失败多因某人只有约 4 秒）。已知人数（取发言最多的 N 组、逐句重新归属）：中文 40/40 场景准确率 ≥ 90%、两组长句回归全对。
- 自动模式无法同时满足所有数据（外放回归里两位不同的人平均 0.44，高于用户会议里同一人被拆开的 0.47～0.55 之下限）——结论：自动尽量准，**参会人数**作为可靠手段，随时可改（经用户同意，逐句声纹随会议保存以支持会后改人数）。
- 实现：`regroup` 自动 / 已知人数两种模式；逐句声纹写入 `meeting_segments.embedding`（增量迁移）；`setExpected` 会中/会后立即重新区分；会中定期归类带上人数；说话人栏加「人数」选择；开始会议的人数提示更醒目。回归数据新增 `test/fixtures/short-turns.json`。
- 验证：58 项测试通过；打包版（数据目录带空格）用 sr-data 拼出的 50 秒二人快速轮流对话（句间 0.4 秒，原声与外放各一）开会，自动模式均判为 2 人、14/17 段全部归对；改为「2 人」结果一致。用户那场会议按 2 人重放（组级）得到两组，与分析一致。
