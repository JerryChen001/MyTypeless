# 2026-10-17 Windows 浮动条按钮点不动

## 现象

真机反馈：快捷键开始 / 结束都正常，但浮动条上的按钮（会议的暂停、结束，听写的取消、完成）用鼠标点击大多失灵。

## 原因（隔离实例 + 自建接点击窗口实测）

浮动条为了不抢焦点设成 `focusable: false`。在 Windows 上，鼠标悬停时页面能收到进入事件、主进程也切到了接受鼠标，但按下与点击事件一个都到不了页面：被 Chromium 吞掉了，也没有穿透到下面。

- 改为可聚焦后点击正常，但会抢走焦点。
- 可聚焦再加上系统的 `WS_EX_NOACTIVATE`：点击正常，但启动后第一次点击仍会把浮动条激活。这时立即 `blur` 会打断点击，而且焦点交给的是 Z 序里的下一个窗口，不是原来的应用。

## 改动

- `mt-focus --no-activate <hwnd>`（Windows）：给窗口加 `WS_EX_NOACTIVATE`。
- `createFloatingBar`：Windows 上可聚焦，再加“点击不激活”样式；设不上时退回 `focusable: false`（按钮点不动，但绝不抢焦点）。
- 鼠标进入胶囊时记下前台应用（`getFrontApp`）；浮动条被点击激活后，等 0.3 秒（让这次点击完成）用 `activateApp` 把前台还给它。
- macOS 不变。

## 验证

- 隔离实例里显示会议按钮，用真实鼠标输入（`mouse_event`）点击，下面铺一个自建窗口接住穿透的点击并作为原前台应用：
  - 改前：0/6 次收到点击。
  - 改后（新实例、未做任何手工修补）：8/8 次收到点击，每次点击后前台仍是原窗口，没有穿透。
- 单测：`mt-focus --no-activate` 参数错误退出码 2、不是窗口退出码 4。`npm run test` 通过。

## 测试方法上的坑

- `SetCursorPos` 不产生输入事件，低级鼠标钩子看不到移动，Electron 的 `forward` 不会转发，所以要用 `mouse_event` 绝对移动。
- PowerShell 进程不感知显示缩放，坐标用逻辑像素。
- 接点击的测试窗口不能置顶：被激活后会盖住浮动条。

## 补充：免手持听写时多出会议的暂停 / 结束按钮

用户截图：免手持听写时，胶囊上除了取消、完成，还显示了会议的暂停与结束按钮，点了没反应（并没有会议在进行）。原因是 `style.css` 的 `.pill.hands-free.state-recording .icon { display: grid; }` 会把所有 `.icon` 都显示出来，而会议按钮也是 `.icon`。这条规则自首次开源（0.2.1）起就有，与平台无关。现在限定为只显示 `.icon.cancel` 与 `.icon.stop`。隔离实例核对：免手持只显示“取消、完成”，会议状态只显示“暂停、结束会议”。
