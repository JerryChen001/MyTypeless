# 2026-10-15 长录音：默认 20 分钟 + 临近上限倒计时（D-014）

## 背景

用户希望单次录音默认最长 20 分钟，并在快到上限时提醒。此前默认 2 分钟（`maxRecordingMs: 120_000`），且到时无提醒、设置界面不可改。提醒方式为原创设计。

## 改动

- 默认 `maxRecordingMs` = 20 分钟；启动迁移：仍为旧默认 120000 的设置改为 20 分钟（界面此前从未提供修改，不会覆盖用户选择）。
- 主窗口设置新增「最长录音时长」（5/10/20/30/60 分钟）。
- 浮动条：`recording` 事件携带 `maxRecordingMs`，按 `elapsedMs` 校准；最后 60 秒胶囊内显示“剩 N 秒”，最后 10 秒变红闪烁。
- 到时自动结束：照常识别、润色、写入，提示“已到最长录音时长（N 分钟），已自动结束”；该提示不写入历史的错误字段。
- 长录音支撑：
  - `LiveTranscriber` 定稿后释放已定稿音频（3 分钟模拟中内存最多保留约 30 秒音频）。
  - 整段识别（云端或实时转写失败的兜底）用 `splitForTranscription` 切成 ≤5 分钟的段，在段尾 10 秒内最安静的 100ms 处下刀：云端 25MB 上传限制（20 分钟 WAV 约 38MB）、本地单段约 10 个 30 秒窗口不超时；云端并行，内置引擎串行。
  - 润色超时 `llmTimeoutMs` = 25 秒 + 每字 30 毫秒，上限 180 秒（几千字的长文本固定 25 秒必超时而退回本地清理）。

## 验证

- 打包版隔离实例（最长录音设为 65 秒）：第 9 秒起无倒计时、进入最后 1 分钟显示“剩 N 秒”、最后 10 秒变红（rgb(255,107,107)）；到时自动结束，提示“已到最长录音时长（1 分钟），已自动结束”。旧设置 120000 启动后迁移为 1200000。
- 发现：65 秒几乎只有环境声的录音被识别成“字幕志愿者 杨栋梁……”（whisper 在噪声上的字幕类幻觉，长录音更易出现）。幻觉过滤移到 `text.ts` 的 `isHallucination` 并补充“字幕志愿者/制作/翻译/校对”，加单测。
- `npm run typecheck`、`npm run test`（43 项）、`npm run build`、`npm run docs:check` 通过。
