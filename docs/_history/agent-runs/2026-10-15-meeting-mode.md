# 2026-10-15 会议模式与主窗口改版（D-015、D-016、D-017）

## 背景

用户提出：界面美化；新增会议模式（个人/会议切换、长时间录音与落地文字、区分人声并命名、每人发言总结、会后会议纪要）。先做需求分析，用户确认：只用麦克风；会议期间录音临时保存、纪要后删除；命名后保存声纹；界面与会议一起交付。整体为原创设计。

## 技术选型与实测

- 说话人区分：sherpa-onnx（Apache-2.0）C API + 声纹模型。官方离线 diarization（pyannote 分段 + 聚类）CPU 上耗时约为音频时长的 24%，1 小时会议结束后要多等十几分钟，因此改为“按句（停顿切分）算声纹、会中在线归类、结束时整体重新归类”，不使用分段模型。
- 声纹模型对比（M2 Pro，单线程，58.6 秒合成语音 12 句、4 个系统朗读声音）：

| 模型 | 大小 | 耗时 / 实时比 | 同人相似度 最小/平均 | 不同人 平均 |
| --- | --- | --- | --- | --- |
| 3D-Speaker CAM++ zh-cn（192 维） | 28MB | 0.92 秒 / 0.016 | 0.847 / 0.894 | 0.395 |
| 3D-Speaker ERes2Net base zh-cn（512 维） | 40MB | 2.49 秒 / 0.043 | 0.860 / 0.895 | 0.321 |

  选 CAM++（快 2.7 倍、效果相当）。系统声音 Eddy 与 Reed 相似度 0.91（同一合成引擎的两个音色，几乎只差语调），其余组合 0.13～0.48；真人区分效果待真机验证。1 小时会议的声纹计算约 1 分钟 CPU（低优先级、单线程）。
- `mt-diarize`：原创 C 程序，静态链接 sherpa-onnx v1.13.8 官方预编译静态库（含 ONNX Runtime），产物 20MB、只依赖系统库。

## 实现

- 主进程 `src/main/meeting/`：分句（停顿 0.6 秒、最长约 20 秒）→ 识别（与听写共用内置引擎，串行）+ 声纹（串行）→ 在线归类（新说话人先查声纹库）→ 定稿即落库；结束时补转写失败句、整体重新归类（合并相似说话人/按参会人数合并、吸收零散说话人、逐句重归，手动指定的句子不动）、保存每人声音特征、更新已关联的声纹 → LLM 生成纪要（头部本地生成；超过约 12,000 字先分段提要再汇总）→ 删除临时录音。
- 异常恢复：启动时把未完成的会议标为“待整理”；“继续整理”会把临时录音中最后一句之后的音频重新分句转写，再照常整理。
- 会议进行中听写被 `session.setBlocker` 拦下；退出应用时提示并先暂停会议；4 小时上限、最后 5 分钟提醒；使用电池时提醒。
- 主窗口改版：左侧导航（个人：首页/历史/词典；会议：会议；共用设置）、首页概览（累计字数、今天、节省时间、平均语速）、快捷键速查、状态卡片、最近记录；历史按日期分组可搜索；词典独立成页（学习开关即时保存）；设置分组、标签对齐；声纹管理在设置里。
- 浮动条：会议录音经同一采集管线（`meetingCapture`），听写空闲时胶囊显示「● 会议中 hh:mm:ss」与暂停/结束。
- 附带：`build/THIRD_PARTY_NOTICES.md`（whisper.cpp、sherpa-onnx、ONNX Runtime 许可证）随包放到 Resources。

- `npm run typecheck`、`npm run test`（54 项，新增 `test/meeting.test.ts` 11 项）、`npm run build`、`npm run docs:check` 通过。
- 打包版隔离实例端到端：把浮动条的 `getUserMedia` 替换为播放一段 42 秒、3 个系统声音轮流说话的录音，走真实采集管线——
  - 7 句话在说完后 1～3 秒内出现，3 个说话人全部归对；结束后状态为已完成、临时录音已删除；未配置 LLM 时给出提示（转写稿完整保留）。
  - 给两人命名并勾选“记住这个声音”，第二场会议中两人被自动标出名字。
  - 会议进行 26 秒时强杀进程：重开后标为“待整理”，“继续整理”从临时录音补转写出崩溃前最后一句并归对说话人，随后删除录音。
  - 会议中调用听写开始：浮动条提示“会议进行中，听写已暂停”。
  - 截图检查首页、设置、会议列表、会议详情（实时转写）、纪要展示（Markdown）、胶囊会议状态。
- 未验证：真人声音的说话人区分效果；真实 LLM 生成纪要的质量（测试环境无 Key，未使用用户的 Key）；长时间（1 小时以上）会议的资源占用。
