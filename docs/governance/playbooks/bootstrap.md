# 流程：初始化文档架构

适用：刚运行 `ai-doc-kit init` 的新项目，或把已有项目接入本文档架构。目标是让 `npm run docs:check` 通过，并把“〔待填写〕”尽量换成**有证据的**真实内容。

## 原则

- 只写能从代码、现有文档或人工回答中得到证实的内容；证据不足的保持“〔待填写〕”并列入最后的问题清单。
- 业务规则、人工门禁、完成标准必须由人确认，不从代码行为反推为“规则”。
- 已有文档不删除：按下文归位，原文移动后在原位置不留副本。

## 步骤

1. **识别项目**：列出顶层目录、构建文件（`Makefile`、`package.json`、`go.mod`、`pyproject.toml` 等）和现有文档。判断是新项目还是已有项目。如果项目原本已有内容不是 `@AGENTS.md` 的 `CLAUDE.md`（或其他工具的规则文件），把其中仍有效的规则合并进 `AGENTS.md`，再把 `CLAUDE.md` 改为只含 `@AGENTS.md` 一行。如果存在 `AGENTS.ai-doc-kit.md`（说明项目原本已有 `AGENTS.md`），把其中的章节结构合并进原 `AGENTS.md` 后删除该文件。
2. **访谈（一次问完）**：向人确认以下内容，未回答的保持待填写：
   - 一句话定位；3～8 条架构原则；
   - 业务领域划分（决定 `requirements/`、`acceptance/`、`decisions/domains/` 和路由任务）；
   - 本项目特有的人工门禁与危险命令；
   - “功能完成”的判定标准。
3. **根 `AGENTS.md`**：填写定位、原则、代码地图（每个顶层代码目录一行）、真实可运行的常用命令、危险命令、人工门禁、完成标准。控制在 150 行以内。
4. **模块说明**：为每个承载业务代码的目录，按 [模块说明模板](../../templates/module-agents.md) 创建 `AGENTS.md` 和 `CLAUDE.md`（内容 `@AGENTS.md`）。“可复制范例”必须是实际存在的文件和函数名，并打开确认过；测试命令必须真实存在。
5. **recipes**：为项目最常见的 3～5 类改动写步骤，每步指向一个真实范例。
6. **决策与需求**：
   - 每个领域创建 `docs/decisions/domains/<领域>.md`（模板见 [decision-domain.md](../../templates/decision-domain.md)），并在决策索引登记已确认的决策。
   - 已有项目：把散落在各处的“已确认规则”归入对应需求文档，把“待确认问题”登记为 B 项，把“当前进度”汇总进 `STATUS.md`，把计划、日志、复盘移入 `docs/_history/`。
7. **术语表**：在 `docs/glossary.md` 各领域分节登记核心概念，并写出对应的代码、接口和表名标识（从代码中核对）；把访谈中发现的混用说法写入“易混淆对照”，已不再使用的说法写入“废弃说法”。
8. **任务路由**：在 `docs/governance/task-routing.json` 为每个领域建一个任务：`read` 为该领域需求、验收和决策领域文件；`search` 为该领域代码目录；`verify` 为真实命令。
9. **STATUS**：写入当前阶段、各领域状态和“必须等待人工”的事项，更新日期。
10. **校验**：运行 `npm run docs:check` 直到通过；运行 `npm run docs:context -- --task <每个任务> --mode implementation` 确认输出合理。
11. **交付**：向人汇报已填写内容、仍待填写的位置（`docs:check` 会统计）和问题清单。是否提交由人决定。
