# 流程：任务收尾

每个任务结束前执行。目的：让下一次任务读到的文档与代码一致，同时不把过程信息塞进日常上下文。

## 1. 同步事实文档（只改受影响的）

| 发生了什么 | 更新哪里 |
| --- | --- |
| 业务规则新增或改变 | 必须先有人工确认：决策领域文件 + 决策索引新增 `D-xxx`；回写需求与验收；关闭相关 B 项 |
| 发现未定义且影响结果的规则 | `open-questions.md` 新增 `B-xxx`；缺口账本对应行标 `INPUT_BLOCKED` |
| 接口变化 | 契约文件（先于代码）及生成物 |
| 表结构或关系语义变化 | 数据模型文档 |
| 缺口状态或验收证据变化 | `gap-ledger.md` 对应行（保持一行简短，证据用链接） |
| 项目/领域状态变化 | `STATUS.md`（并更新“最后更新”日期）；其他文档不复述状态 |
| 目录结构、范例、不变量或测试命令变化 | 对应目录 `AGENTS.md`；新增顶层目录时同步根 `AGENTS.md` 代码地图与任务路由 |
| 出现新的常见改动模式 | `recipes.md` |
| 新概念、概念改名或发现同一概念被叫成不同名字 | `glossary.md`（改名时把旧说法登记到“废弃说法”） |

## 2. 写过程记录

按[运行记录模板](../../templates/agent-run-log.md)写入 `docs/_history/agent-runs/YYYY-MM-DD-<主题>.md`，保持简短：范围、改动、验证结果、遗留。改动很小（如错别字、单行修复）时可以省略。

过程记录只放在 `_history/`，不要把“本轮做了什么”写进需求、决策、缺口账本单元格或模块说明。

## 3. 校验

1. 运行任务路由给出的验证命令。
2. 运行 `npm run docs:check`。

## 4. 汇报

向人说明：改了什么、验证结果（含失败）、新增的 B 项和需要人工裁决的问题。
